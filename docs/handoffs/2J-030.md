## Important runtime boundary

The live app is intentionally fail-closed for booking and waitlist writes until a server-owned resolver can verify a client's plan assignment and available balance. That source is not present in 2J-020, and this TASK explicitly excludes financial consumption. The `BookingEligibilityResolver` contract is in place; PostgreSQL API tests inject an eligible resolver to verify reservation, cancellation, capacity race, waitlist, audit, and client-link behavior. No eligibility or balance is fabricated in the default runtime.
