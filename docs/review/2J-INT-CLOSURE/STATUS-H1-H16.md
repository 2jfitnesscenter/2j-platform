## Measurements requested by the review

- **Kiosk latency after a Platform suspension** (`tooling/e2e/kiosk-suspension-latency.mjs`, real processes, 250 ms polling, 8 trials at random cache ages): **8 of 8 blocked**; latency min 7.3 s, p50 19.2 s, p95 = max 39.7 s; latency + cache age = 60.0–60.3 s in every trial. So the bound is **≈ 60 s + the polling interval**, as designed — measured on a loopback with synchronised clocks, n = 8; **not declared guaranteed**. Restoration after a lift also takes ≈ 60 s (60.0–60.2 s).
- **Platform stopped, nobody acts:** the kiosk kept answering 200 for the whole 75 s observed (the free baseline includes `autonomousTraining`). **Local emergency disable:** first 401 after 6–7 ms. Raw: `EVIDENCE-kiosk-latency.json`. Procedure: `docs/runbooks/2J-INT-emergency-suspension.md`.
- A first run of the harness had a flaw (it polled an invalid token after failed check-ins, so half of the trials reported no block); it was fixed and rerun; only the fixed run is reported.
