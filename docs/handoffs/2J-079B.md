# 2J-079B — Local pilot harness

## Goal and boundary

One Windows command starts the local member preview, Trainer workspace and Admin workspace with their own API processes. This is strictly local development. The harness does not alter production authentication or infrastructure, Training, or `2jfitnessapp`, and it must only use synthetic data.

## Start and stop

From the repository root, with Docker Desktop running:

```powershell
pnpm pilot
```

On the first run the launcher installs the frozen workspace dependencies if needed. Use the URLs it prints. The member link contains the explicit `?preview=1` opt-in and displays fictional fixture content. Stop the web/API processes with `pnpm pilot:stop`. The database and named volume persist between runs; no data-reset or destructive cleanup is performed by the launcher.

## Runtime topology

- Member: Vite client-app, preferred port 5173; fallback ports begin at 5180. Fixture preview only, API-free.
- Admin: admin-web, preferred port 5174; its API is a separate `NODE_ENV=development`, `LOCAL_DEMO_ROLE=admin` process, preferred API port 8789.
- Trainer: staff-app, preferred port 5175; its API is a separate `NODE_ENV=development`, `LOCAL_DEMO_ROLE=trainer` process, preferred API port 8788.
- Database: dedicated loopback-only PostgreSQL 17 container `2j-platform-079b-pilot`, database `2j_demo`, port 55436 and named volume `2j-platform-079b-pilot-data`.

Admin and Trainer share the synthetic database but not API process state or demo role. Migration execution uses the existing PostgreSQL advisory lock; the deterministic demo seed is additive and uses `ON CONFLICT DO NOTHING`. Each API has a CORS origin matching its own UI. Every app and API binds to `127.0.0.1`; the harness does not kill unrelated processes if ports conflict. It chooses a free web/API fallback port and reports it; the dedicated database port must be free.

Process logs and runtime PID metadata are stored under `%LOCALAPPDATA%\2J\platform-local-pilot`, outside the repository. Stop only targets process IDs recorded by this launcher and verifies the process command line before terminating that process tree. Stop preserves the database and synthetic rows.

## Safety

Do not use production credentials, real member data, production databases, or publicly expose any demo-role API. The member preview is fictional, explicitly opted in, and does not make API calls. Staff/Admin demo roles are development-only backend shortcuts. Production identity/auth is unchanged and not provided by this harness. The Training app remains `https://app.2jfitnesscenter.com`; this task makes no changes to Training, `2jfitnessapp`, deployment, DNS, TLS, Cloudflare, or production infrastructure.

## Verification

The launcher performs these checks on every start: dependency directory exists; Docker is available and running; the dedicated container is either absent or has the expected ownership label/database config; database is ready; migrations pass; synthetic seed completes; both API `/health` endpoints and all three web entry points respond. On readiness failure, it stops the process trees it started and retains the local synthetic database for inspection/retry.
