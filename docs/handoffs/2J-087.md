## Delivered

Center News is its own PostgreSQL domain (`center_news` and append-only `center_news_audit_events`), separate from general or recipient-targeted notifications. Inicio no longer reads `center_notice`; the existing notification APIs and inbox remain intact. No old notifications were migrated into News.

Admin has a permission-gated Noticias section for draft creation/edit, publish, withdraw, feature/unfeature, current status and audit history. The API records the authenticated actor on each mutation. Admin authorization is enforced by `news.manage` for writes and `news.read` for listing/history; the current approved role matrix grants management only to Admin. The shell only displays the navigation entry when its server-provided capability is true.

`GET /api/me/news` requires an active authenticated client facet but does not require booking-cohort membership or an entitlement. It returns only published, currently visible items scoped to center `2j`, ordered newest first, plus the newest currently visible featured item or the newest published fallback. The News list/detail view returns to Inicio, which remains highlighted in the bottom navigation. Empty and load-error states are distinct.

Preview remains fixture-only and zero-API; its News content is fictional. The Member Home stays within its existing three primary blocks and five-tab navigation. Training, Store, Profile, auth, and booking behavior were not expanded.

## Data and state rules

`draft` is hidden and editable; `published` is visible and editable; `withdrawn` is retained, hidden from Members and not editable. Republish from `withdrawn` is supported and receives a new publication timestamp. Feature state is only valid for `published`; withdrawal clears it. Equal publication timestamps are ordered by ID. There is no scheduling UI or window in V1; immediate publication is used.
