# RM-00-04 — Shared destructive confirmation and save state

## Objective
One accessible confirmation dialog (with optional/required reason) and one save-state indicator in the V2 design system, adopted in one example module. Source: `COMPETITIVE-IMPROVEMENT-ROADMAP-V2.md` RM-00-04 (audit rows T9, T10; P2, S).

## Scope delivered
- `ConfirmDialog` and `SaveState` in `@2j/ui` (exports, styles with existing tokens, unit tests).
- Adoption in Noticias: withdrawing a news item uses `ConfirmDialog` instead of `window.confirm`; the success/saving message uses `SaveState`.
- Documented in `docs/design-system/foundation.md`.

## Out of scope
- Migrating the other `window.confirm` calls (Servicios, Tienda): their files belong to open PRs #51/#52. RM-07-04 (void sales with reason) will be the first consumer with a required reason.
- API, DB, RBAC, Member, RM-00-05.

## Acceptance
- Dialog: alertdialog, focus trapped, Escape closes, focus returns, reason required when configured (tests).
- Documented in docs/design-system. Example module works (Noticias test + browser check).
- Handoff: `docs/handoffs/RM-00-04.md`. No owner gate.
