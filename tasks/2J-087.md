# 2J-087 — Center News V1

**Status:** implementation complete; one Draft PR; not merged.
**Base:** `0d2e30661c2f56e07f8c2d8e0cff68ffbebcf037`
**Scope:** editorial News for Admin and Member Home; notifications remain an independent domain.

## Acceptance criteria

- Admin-only server capabilities create, edit, publish, withdraw, feature and unfeature Center News.
- Every successful administrative mutation records actor, action, timestamp, and bounded field/status details in append-only audit history.
- Members with an active authenticated client facet can read published Center News without a booking cohort or active entitlement. Drafts, withdrawn items, other center scopes, and future `published_at` values remain invisible.
- Member Inicio selects the newest visible featured story, otherwise newest visible story, and has a distinct empty/error state. A simple list/detail view returns to Inicio while preserving Inicio as the active bottom-nav destination.
- Inicio reads the News API in normal mode. `center_notice` notification rows no longer drive Noticias; notification endpoints and inbox behavior remain unchanged.
- Preview uses fictional News fixtures and makes zero API calls.
- Add a checksummed additive PostgreSQL migration and cover API, permissions, Admin UI, Member UI, and relevant regressions.

## V1 rules and bounded limitations

Publication is immediate. Drafts can be edited; published items can be edited; withdrawn items remain visible to Admin with their history and can be republished, but cannot be edited. Featuring is only available while published. Withdrawal automatically clears the featured flag. When several visible stories are featured, the newest `published_at` wins with ID as deterministic tie-breaker; if none are featured, the same ordering chooses the Home story. News body/title are plain text; React renders escaped text and the API rejects HTML-like tags.

Scheduling windows, media, rich text, categories, tags, public sharing, reactions, comments, analytics, and publish-triggered notifications are deferred. Admin edits use last-write-wins; no generic optimistic-version framework was added. The Member list is capped at 100 items without cursor pagination.
