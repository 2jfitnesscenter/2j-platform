# TASK 2J-094 — Professional Shell & Navigation

## Objective

Establish one capability-driven, Atlas-inspired professional desktop shell for Admin and Trainer while retaining existing Platform routes and product domains. Member Hub, the Staff mobile app, Training, backend APIs, and database schema remain outside this task.

## Approved product decisions

- Member continues to use the separate Member Hub.
- Admin and Trainer share one professional desktop shell; navigation visibility derives from `GET /api/session/capabilities`, never from a role label or viewport.
- The professional mobile hybrid (`Mi 2J / Trabajo`) is a later task.
- Training remains an external/integrated domain. Do not add Programación, Entrenamientos, Athlete View, or Arena.
- No activity timeline is introduced; Actividad opens the existing communications inbox.
- No new API or migration is expected.

## Scope

- Introduce the six top-level locations: Resumen, Actividad, Clientes, Mi gimnasio, Equipo, Negocio.
- Group existing hash routes with accessible nested navigation, active-state context, responsive shell behavior, and the existing global search.
- Preserve the existing page components and route semantics.
- Fail closed for unavailable capabilities and retain server-side route authorization.

### Route mapping

| Location | Existing route(s) |
| --- | --- |
| Resumen | `#home` |
| Actividad | `#communications` |
| Clientes | `#clients` |
| Mi gimnasio | `#calendar`, `#services` |
| Equipo | `#staff` |
| Negocio | `#economics`, `#store`, `#news`, `#notification-settings` |

`#services` appears once, under Mi gimnasio, because the current page combines areas, services, plans, and rights and is the primary operational configuration for scheduling. Do not duplicate its route under Negocio.

## Acceptance criteria

- Admin and Trainer use the same shell and see only groups/routes allowed by current capabilities.
- Groups disappear when none of their destinations are allowed; partial capability sets expose only permitted links.
- Existing deep links, hash/query state, route-specific API checks, and global search continue to work.
- The shell communicates current location and retains readable labels, focus visibility, semantic links/buttons, and active-route semantics.
- Desktop is checked at 1440×900 and 768×1024; 390×844 is a catastrophe-only shell check, not a mobile redesign.
- Existing routes render without a content redesign.
- No API source, migration, Member Hub, Staff app, or Training source changes.

## Validation

- Admin navigation tests cover broad Admin, Trainer, partial/limited capabilities, hidden groups, active route/context, deep links, preserved global search, and excluded top-level modules.
- API integration regression ensures Trainer cannot access business APIs without the exact capability.
- Run full tests, typecheck, build, audit, migration verification, and `git diff --check`.
- Record browser observations, responsive limitations, theme support, accessibility, CI, changed files, and remaining findings in `docs/handoffs/2J-094.md`.
