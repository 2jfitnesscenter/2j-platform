# Handoff — RM-00-04 (confirmación destructiva y estado de guardado comunes)

P2, S. Componentes en `@2j/ui` y adopción en Noticias. Sin API, DB, migraciones, RBAC ni Member. Puerta del dueño: ninguna.

## Qué cambia

| Pieza | Dónde |
|---|---|
| `ConfirmDialog`: `alertdialog`, foco inicial en Cancelar, Tab contenido, Escape y clic fuera cancelan salvo `busy`, devuelve el foco a quien lo abrió, motivo opcional u obligatorio (`minLength`), botón final rojo relleno solo en `tone="danger"`, `error` anunciado | `packages/ui/src/confirm-dialog.tsx` |
| `SaveState`: región viva siempre montada; guardando, guardado y error con icono y texto; error asertivo | `packages/ui/src/save-state.tsx` |
| Exportaciones y estilos (solo tokens existentes) | `packages/ui/src/index.ts`, `ui.css` (bloque nuevo al final) |
| Adopción: retirar una noticia abre el diálogo (antes `window.confirm`); el mensaje de guardado usa `SaveState` | `apps/admin-web/src/news-page.tsx` |
| Documentación y contratos | `docs/design-system/foundation.md` |
| Tests | `packages/ui/test/ui.test.mjs` (5 nuevos), `apps/admin-web/test/news-page.test.mjs` (flujo de retirar vía diálogo) |

## Decisiones

- El diálogo reutiliza las clases `ui-modal*` que ya existían en `@2j/ui`; no se rediseña nada.
- La retirada de noticias no envía motivo (la API no lo admite), así que el ejemplo usa el diálogo sin motivo. El motivo obligatorio queda probado en el componente y lo consumirá RM-07-04.
- No se migran los otros `window.confirm` (Servicios y Tienda): sus archivos pertenecen a #51 y #52.

## Verificación

Tests de `@2j/ui`, admin-web, typecheck y build. Comprobación visual en el navegador integrado: Noticias → Retirar.
