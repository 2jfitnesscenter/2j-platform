# TASK 2J-095 — Professional Operational Summary

## Objective

Redesign the professional `Resumen` / Command Center for Admin and Trainer as a compact, actionable operational home. Reuse the existing dashboard read model and server-derived capabilities. Keep Member, Staff, Training, financial policy, and unrelated verticals out of scope.

## Product rules

- Show three to five actionable blocks, prioritizing today's agenda and items needing attention.
- Admin may see economic summaries only when the API grants the billing capability; cash details also require the cash capability.
- Trainer sees operational information available to that actor and no economic data.
- Do not infer authorization from role labels or hide data only in the client; consume the already-filtered server response and its capability flags.
- Use `Atlantic/Canary` for dates and times.
- Keep loading, failure, and genuinely empty states distinct, with retry on failure.
- Use existing 2J design tokens in light and dark themes.

## Scope delivered

- Replaced the prior vanity-metric/customizable dashboard with blocks for today's agenda, attention, pending work, team pulse, and permitted economic status.
- Added safe in-app deep links to the existing calendar, communications, staff, and economics areas.
- Kept API authorization and domain boundaries intact; the only API read-model adjustment separates the unassigned-session timestamp from its human-readable context.

## Acceptance and verification

- Admin and Trainer variants are capability-aware; limited actors receive only authorized operational content.
- Agenda and attention states include empty, loading, and error/retry behavior.
- Responsive acceptance targets: 1440×900, 768×1024, and 390×844.
- Keyboard focus is visible; semantic links and headings describe the page hierarchy.
- Full test suite, typecheck, build, migration verification, dependency audit, and `git diff --check` are required before completion. Record exact results in `docs/handoffs/2J-095.md`.

## Out of scope

No new activity timeline, client-health or training data, new API endpoints, schema/migration changes, Member Hub or Staff redesign, fiscal changes, or production infrastructure changes.
