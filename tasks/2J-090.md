# 2J-090 — Store V1

Status: implementation complete; Draft PR [#37](https://github.com/2jfitnesscenter/2j-platform/pull/37) pending CI and independent review; do not merge.

## Scope and ownership

Store owns its fixed V1 categories (`nutrition`, `merchandising`), products, variants, display prices, variant-level inventory ledger, internal sales, immutable sale-line snapshots, and Member-linked purchase history. Member/person identity remains owned by Platform and is resolved from the authenticated server context. Store does not own plans, bookings, Training, online payments, shipping, or ecommerce carts.

## Domain and lifecycle

- Products use a bounded category enum and can be deactivated; destructive deletion is unavailable.
- Variants support SKU, label, optional size/flavor, integer-cent price, active state, and explicit stock tracking.
- Inventory is derived from append-only opening/restock/adjustment/sale/reversal movements. Sale creation locks variants, checks authoritative stock and prices, records immutable snapshots, and writes movements in one transaction.
- Sale creation requires a UUID idempotency key. Same key and payload replays the sale; a changed payload returns a conflict.
- Completed sales are immutable. Void is one-way, restores tracked units through reversal movements once, and preserves the original sale, lines, movements, and audit.
- Payment state is operational (`paid` or `pending`); no payment rail is contacted. Prices are final display prices without tax decomposition. Any future fiscal detail must use IGIC terminology and an approved rate.

## Permissions

| Capability | Admin | Trainer | Reception/Management | Accountant | Member |
| --- | --- | --- | --- | --- | --- |
| Staff catalog/inventory/sales APIs | Yes | No | No | No | No |
| Browse active catalog | No staff API required | No staff API required | No staff API required | No staff API required | Authenticated self |
| Read own purchase history | — | — | — | — | Authenticated self |

The current role model does not explicitly authorize POS for staff. Sale creation remains Admin-only until a role decision grants specific Store capabilities.

## Member and Admin experience

Member Store is informational and filters Nutrición/Merchandising. It shows variants, final display price, and coarse availability only; it has no cart or checkout. Profile → Tickets y compras reads only the active authenticated Member's history. Admin has one Store area for catalog, variants, stock adjustments, internal POS, recent sales, and voids.

Preview uses fictional products and one fictional purchase, stays zero-API, and disables mutations.

## Deferred

Online checkout/cart, payment processors and terminal integration, shipping/delivery, discounts, subscriptions, supplier purchasing, refunds through real rails, invoice generation, IGIC rates/tax breakdown, Member-created orders, and staff POS grants are outside this task.
