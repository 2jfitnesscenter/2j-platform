# Handoff — 2J-078B Shared person identity / Training contracts

## Approved identity decision

`personId` is the opaque, immutable, lifetime-stable identifier shared by Platform and Training. `clientId` and `staffId` are Platform-local facets. A person who is both client and staff has one `personId` and at most one active Training link. Training keeps its own roles and permissions. No email/phone matching is permitted.

Training stores only `linkId`, `personId`, `trainingUserId`, `status`, `method`, `linkVersion`, lifecycle timestamps, and audit actors. It never stores central client/staff IDs or a copied central profile. Revocation addresses `personId`.

## Implemented in this branch

- Additive migration `0022_person_training_identity.sql` creates stable Platform persons, separate client/staff facet links, canonical Training account links, uniqueness guards, lifecycle constraints and append-only identity audit.
- API contracts are strict, versioned, and person-scoped. Admin-only Platform APIs create/read person subjects and add local facets. Synthetic canonical link create/revoke is separately gated by server option `trainingLinkingEnabled`, defaults OFF without environment opt-in, and returns `423 training_linking_disabled` while OFF.
- When explicitly enabled, link `active` means only that a synthetic local foundation record exists. It is not evidence of remote Training acknowledgement. `explicit_admin` records the local actor action and is not proof-of-possession; it must never be represented as `user_confirmed`.
- `identity.people.manage` is registered, granted only through the Admin wildcard, and server authorization is deny-by-default.
- Read-only Training summary adapter does not call by default, requires explicit enablement, URL, fetch implementation and injected signer, has a deadline, validates the person-scoped response, and reports provider failures without affecting Platform operations.
- No Training checkout, code, database, or configuration was changed. No credentials, SSO, user matching, entitlement enforcement, UI, or booking/payment flows were added. Training LIVE linking remains OFF; the read adapter is independently disabled unless separately configured with an injected signer. Remote Training link creation/revocation, remote acknowledgement, dual proof, SSO, and access enforcement are not implemented.
