# 2J-076 — App Staff V1

Status: implementation in review; this is a draft PR from `agent/codex/2J-076-staff-app`, based on `13261c64f613f5e95af21437c57171d07c0c9a07` (2J-075 merge). Do not merge until independent product/security and UX review.

## Product surface

`apps/staff-app` is a separate React/TypeScript/Vite app, PWA shell, and Capacitor target (`com.2jfitness.staff`). Bottom navigation is Home, Agenda, Clients and More, with destinations hidden based on the central session capability response. There is no role picker or separate login. Tablet/desktop uses the same compact operational UI rather than reproducing Admin Web.

## Connected flows

- Home and a single-day agenda use `/api/calendar/week` and `Atlantic/Canary` formatting.
- Session detail reads attendees and waitlist; attendance and no-show changes go to the existing audited attendance endpoint.
- Staff reservation starts from a client search, calls the existing booking eligibility resolver endpoint, then the existing reservation or waitlist route. The client/session/action tuple retains an idempotency key across retries. Overrides are not surfaced from this first mobile slice; ordinary eligibility and backend denials remain authoritative.
- Client search is bounded to 20 results. Client profile uses the existing 360 endpoint. Entitlement details and fixed-price plan assignment use existing entitlement/catalog APIs and leave the resulting charge pending.
- Messages read the existing inbox and client conversation; sending is shown only after the server capability indicates `communication.send`.
- Own timeclock reads `/api/timeclock/self` and posts the `staff_app` origin; identity is resolved server-side.
- Team summary is shown only where `staff.read` is granted.

## Identity, permissions and privacy

No changes to auth/session resolution. `/api/session/capabilities` was extended with boolean, actor-local capability flags so the shell can adapt to roles without inferring role names. Every write/read still calls the source domain API, which independently enforces the permission. Failures and expired authentication do not fall back to demo data. The service worker caches only shell/static files and bypasses all `/api/` traffic; fetches use credentials and `cache: no-store`.

## Limits before production

- Staff account authentication must be hosted on the same trusted API origin/cookie policy as the central web session. Capacitor native-origin/cookie behavior and allowed deployment origin must be validated; this TASK does not broaden CORS or implement a parallel token login.
- Cash drawer, payment collection, cash open/close, cash balances and fiscal operations stay in the current economy surface. This first app does not yet offer an in-app payment/cash flow.
- Plan assignment supports new fixed-price plan assignment only. Renewal/change/pause/cancel flows and plan price overrides are not included. It uses the catalog price and leaves a charge unpaid; no payment is created.
- Detailed document review, form completion, sensitive health data, staff profile/absence editing, session cancellation, reservation cancellation, waitlist removal/promotion, and reasoned debt/document/capacity overrides are not yet wired into this mobile UI.
- No real role-session browser walkthrough or screenshot was generated in this environment; UI tests use explicit API fixtures and must not be represented as production/demo credentials. Responsive review remains for independent QA at 390, 768 and 1440 px.
- No schema or migration changes. No `2jfitnessapp` or Client App changes.
