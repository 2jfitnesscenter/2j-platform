## Product result

The Member bottom navigation is exactly **Inicio · Búnker · Tienda · Perfil · Ajustes**. Inicio is limited to three primary blocks: Noticias, Reservar clase, Próxima reserva. It has no extra dashboard cards. The main CTA enters the existing weekly booking flow; Mis reservas opens the existing upcoming/waitlist/history destination. No booking rules or API contracts changed.

The next reservation is the nearest future booking whose booking status is `reserved`, excluding entries whose session is cancelled. Waitlist entries, cancelled bookings and past items are not selected. The card shows service, Atlantic/Canary date, start/end, area and “Confirmada”; no upcoming entry produces “No tienes ninguna reserva próxima.”

Noticias temporarily selects the newest visible `center_notice` from the Member notification response. General notifications are not treated as the final News domain; they remain accessible through the Buzón and header notification entry. Real admin-managed center News is deferred.

Búnker opens `https://app.2jfitnesscenter.com` in a new tab using the existing external handoff; no iframe, SSO, API or Training repository changes. Tienda is an informational shell for Nutrición and Merchandising with the copy “Catálogo informativo. Las compras se gestionan directamente en el centro.” It contains no real catalog, products, prices or checkout. Perfil preserves the current member identity, membership/rights, form and consent capabilities, and links to the existing Buzón. Unsupported sections are omitted. Ajustes is an empty global-settings shell; internal pilot links remain development/preview-only.

Preview stays build-gated plus exactly one `preview=1`, uses fictional fixtures, performs zero API calls and persists no changes. 2J-084 session/auth/CSRF and 2J-085 cohort/booking pilot behavior were not modified.

## Visual/browser QA

The in-app browser smoke confirmed Inicio's three blocks, five destinations, weekly reservation browser, external Búnker target, and Tienda/Perfil/Ajustes shells in fixture preview. A separate disposable synthetic pilot database was used to log in as Member A and B: A browsed, cancelled a synthetic reservation, joined and left the waitlist; B remained read-only with the cohort explanation. Existing API tests cover reserve, CSRF and cohort enforcement. The available in-app browser does not expose exact viewport override or screenshot export; the inspected viewport was approximately 491×741. Therefore this handoff does **not** claim 1440, 768 or 390 viewport captures. Responsive behavior is covered by CSS breakpoints, five-item navigation sizing, accessible labels/focus styles and automated UI tests, but exact-size visual review remains an independent UX check.

Accessibility checks: navigation uses buttons with `aria-current="page"`; text labels supplement icons; active navigation has an indicator in addition to color; focus-visible styles and 44px+ targets remain; bottom navigation accounts for safe-area insets; reduced-motion rules are retained. Dialog flow and booking code were not changed.
