## Cambios

- El quickstart usa una base `2j_platform_local` vacía y no ejecuta `seed:demo`. La demo continúa como opt-in, aislada en una base desechable `2j_demo`; nunca se limpia ni elimina información automáticamente.
- El Command Center muestra la agenda local de hoy ordenada por hora con servicio, profesional, ocupación, plazas libres, lista de espera y estado en curso. Los resultados están limitados por el permiso de calendario y no incluyen datos de clientes.
- `POST /api/calendar/templates/batch` crea plantillas en lote reutilizando `recurring_session_templates`. Valida días/franjas, fechas, límite de 50 combinaciones y solapamientos; cualquier conflicto aborta todo el lote. No genera sesiones automáticamente.
- Las creaciones en lote registran `template.created` mediante la nueva migración aditiva `0015_bulk_template_audit.sql`.
- La UI presenta vista previa de la matriz, feedback de guardado y el CTA `Crear tu primer horario` cuando la semana está vacía.
- La navegación de Comunicación se comprueba durante cambios de módulo manteniendo el permiso activo.

## Decisiones y límites

- No se eliminan seeds ni filas de bases existentes. La base local limpia es una base nueva y separada.
- No se añaden entidades de horario, reglas de recurrencia, recursos ni salas. Se usan las plantillas existentes y la generación de sesiones sigue siendo manual.
- No se modifica 2jfitnessapp ni entrenamiento/Búnker/Health, pagos, permisos ni lógica de comunicaciones.
