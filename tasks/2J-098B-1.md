# 2J-098B-1 — Solape de profesional

> Lee primero `docs/architecture/epics/2J-098-master.md` (secciones `CONCURRENCY MODEL`, decisión B-02).

## Objective

Garantizar en la base de datos que **un profesional no tiene dos sesiones `scheduled` solapadas**, sin corregir datos históricos automáticamente. Dos PRs con una puerta humana entre ambos.

## Context

La invariante hoy solo existe en las rutas manuales con advisory lock por profesional (F-12). El materializador y el alta de plantillas pueden crear conflicto plantilla/sesión manual. Decisión B-02: informe READ ONLY → propuesta → decisión humana → corrección con operaciones explícitas → restricción fuerte.

## In scope

### PR a) Informe y herramienta de resolución (sin migración)

1. Script **READ ONLY** (`SET TRANSACTION READ ONLY`) que lista todos los solapes reales: ids de ambas sesiones, fecha/hora local, profesional, servicio, origen (`manual`/`template`), nº de reservas y de espera afectadas.
2. Propuesta de resolución **por conflicto** (reasignar profesional, mover, cancelar con restauración) como texto; no se aplica nada.
3. Runbook `docs/runbooks/professional-overlap-resolution.md`: cómo corregir con las operaciones existentes (editar sesión, reasignar, cancelar sesión).
4. Salida CSV/JSON para revisión del propietario.

**Puerta humana:** el handoff registra la decisión del propietario sobre cada conflicto y la confirmación de que el informe sale vacío.

### PR b) Restricción fuerte (tras la puerta humana)

1. **Spike previo documentado**: columna `ends_at` generada con expresión inmutable (p. ej. `timestamp` en UTC + `make_interval` y de vuelta a `timestamptz`), disponibilidad de `btree_gist` (extensión "trusted" desde PostgreSQL 13), `ON CONFLICT DO NOTHING` frente a exclusión, tiempo de reescritura de tabla.
2. Migración: `btree_gist`, `ends_at`, `EXCLUDE USING gist (professional_id WITH =, tstzrange(starts_at, ends_at, '[)') WITH &&) WHERE (status='scheduled' AND professional_id IS NOT NULL)`. **Pre-comprobación dentro de la migración que falla con un mensaje claro y recuento si quedan solapes** (nunca mueve, borra ni omite sesiones).
3. Mapeo de errores: `23P01` → `professional_session_conflict`; `40P01` reintento único.
4. La comprobación previa de aplicación se conserva para avisos y overrides de disponibilidad; el conflicto de solape sigue sin poder sobrescribirse.
5. Materializador/alta de plantilla: cuando una ocurrencia choque, se registra `template.occurrence_conflict` (cuenta esperadas frente a insertadas) y queda visible; nunca se descarta en silencio.

## Out of scope

Corregir datos automáticamente; exclusividad por área/sala; mover el materializador a un worker (B-2); cambios de UI de Agenda.

## Dependencies

a) 098-0. b) B-0 y la puerta humana de a).

## Domain invariants

- Ninguna vía (API, materializador, SQL directo) puede dejar dos sesiones `scheduled` solapadas del mismo profesional.
- Sesiones consecutivas (fin = inicio) no chocan.
- La migración jamás modifica filas de sesiones ni reservas.
- Sesiones sin profesional no entran en la restricción.

## Files likely affected

`apps/api/scripts/`, `docs/runbooks/`, `apps/api/migrations/`, `apps/api/src/calendar.ts`, `apps/api/src/calendar-materializer.ts`, `apps/api/src/schema.ts`.

## Migration

Solo en b): extensión, columna generada, restricción. Test de migración: falla con solapes preexistentes (mensaje y recuento), aplica con datos limpios, no altera filas.

## Feature flags

Ninguno (la restricción es de BD). El mapeo de errores es compatible hacia atrás.

## Tests

- Informe: detecta solapes manuales, de plantilla y mixtos; no escribe (transacción de solo lectura).
- Dos POST simultáneos del mismo profesional → un 201 y un 409.
- PATCH que mueve una sesión al hueco de un POST simultáneo.
- Dos PATCH que intercambian profesionales (descartar deadlock).
- Plantilla contra sesión manual: evento de conflicto, sin pérdida silenciosa.
- Edición de ocurrencia, fin = inicio permitido, DST.

## Manual acceptance

Propietario revisa el informe y decide cada conflicto antes del PR b). Tras b), intentar crear dos sesiones simultáneas del mismo profesional muestra el error existente.

## Risks

Datos reales con solapes (mitigado por la puerta humana); expresión generada no inmutable (spike); privilegios de extensión en el hosting; descartes silenciosos del materializador (evento obligatorio).

## Definition of Done

Informe vacío confirmado y registrado; restricción activa; tests de concurrencia verdes; revisión de SHA exacto; handoff con decisiones humanas.

`docs/handoffs/2J-098B-1.md`: informe original (anonimizable), decisiones y operaciones aplicadas, resultados del spike, tiempos de migración.
