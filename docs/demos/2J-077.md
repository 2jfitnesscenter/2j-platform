# 2J-077 — Demo checklist

Use only configured local/staging test accounts and real API responses. This page is a runbook, not evidence that the screens were captured or that a production delivery provider is configured.

## Client inbox

1. Create a client session and confirm the bell displays the server unread count.
2. Reserve a session; after the worker runs, confirm the inbox contains one generic “Reserva confirmada” item.
3. Mark the item read, refresh, and confirm it remains read and the unread badge falls.
4. Create enough notices to paginate; load older notices and confirm there are no duplicate IDs.
5. Switch to another client session and confirm the first client’s entries and read state are unavailable.

## Waitlist promotion

1. Fill a session and add an eligible client to its waitlist.
2. Confirm a generic waitlist notice appears for that client.
3. Cancel the active reservation; the existing transactional promotion flow appends a promotion event.
4. Run the worker and confirm only the promoted client receives “Plaza disponible”.

## Reminder and entitlement notices

1. In Admin Web → Avisos, set a short valid lead time and save. Verify a non-admin role receives `403` for settings writes.
2. Create a future reserved session whose computed due instant is within the worker schedule; confirm one reminder after due time.
3. Create an expiring assignment, low-balance assignment and assigned document in test data. Confirm generic notices only and one item per dedupe key after repeated worker runs.
4. Repeat around the March and October DST transitions; stored timestamps remain instants, local expiry date boundaries use `Atlantic/Canary`.

## Staff message and substitution

1. Send a client message. Active staff with `communication.read` receive generic notice text; a Trainer without that permission does not.
2. Send a staff message and confirm only the addressed client receives its generic notice; no message body is copied into the outbox or notification row.
3. Create a substitution between active professionals. The source and substitute staff actors receive the generic coverage notice; unrelated staff do not.

## Required visual review

Open the actual authenticated client, staff and admin apps at 1440, 768 and 390 px. Check bell/badge, inbox list, empty state, long content, keyboard focus and touch targets. No browser screenshots are currently attached; fixture-based tests must not be presented as browser captures.
