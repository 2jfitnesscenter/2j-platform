# 2J-098-0 — Cimientos del EPIC 2J-098

> Lee primero `docs/architecture/epics/2J-098-master.md`. No reinterpretes decisiones aprobadas.

## Objective

Dejar listas las piezas compartidas que usan todas las tasks del EPIC, **sin cambiar ningún comportamiento de producto**: reloj y fechas de Canarias, auditoría compartida, relajación de los CHECK de eventos, metadatos del registro de permisos con su test golden, y utilidades de test.

## Context

- Master: secciones `TIMEZONE MODEL`, `AUDIT / EVENT MODEL`, `RBAC MODEL`, `TEST STRATEGY`.
- Hechos F-8 (auditoría y outbox con listas cerradas) y F-13 (permisos del Trainer) del master.
- El driver devuelve `date` como `Date` de JS; ya hubo un bug por ello (comparación de cadena con `Date`).

## In scope

1. **Reloj y fechas:** puerto `Clock` (TypeScript) y utilidades puras de `Atlantic/Canary` (fecha local, inicio del día siguiente, suma de días sobre `date`; la aritmética de meses de contratos NO va aquí: la define E-1 con `calculateContractEnd`). Función SQL `canary_date(timestamptz)`. Sin reglas de negocio todavía.
2. **Tipo `date`:** configurar el parser de postgres.js (OID 1082) para devolver `'YYYY-MM-DD'` como texto, tras auditar todos los usos existentes (`grep` + tests) y ajustar los que dependan de `Date`.
3. **Auditoría compartida:** tabla `platform_domain_audit_events` (append-only, guarda de TRUNCATE, `domain` y `action` validados por regex, `actor_id`, `actor_kind`, `resource_type`, `resource_id`, `correlation_id`, `reason_code`, `reason_text`, `details jsonb`, `occurred_at`) y helper TypeScript del "sobre de auditoría" común.
4. **Eventos:** relajar los CHECK de `domain_events_outbox.event_type`, `notifications.type` y el regex de `deeplink` a formato + registro en código (los valores actuales siguen siendo válidos).
5. **Registro de permisos:** convertir `knownPermissions` en un registro con metadatos (`domain`, `description`, `sensitive`, `delegable`, `dependsOn`, alcances admitidos) **sin cambiar las concesiones de ningún rol**. Clasificar cada clave existente frente a la lista de no delegables (R-03). Añadir el **test golden**: permisos efectivos de los 4 roles = snapshot actual.
6. **Utilidades de test** (`packages/testing`): reloj inyectable, ayudante de concurrencia con barrera, guarda de "base limpia" para la suite, fábricas básicas.
7. ADR esqueleto (`docs/adr/`) para: derechos por fórmula L–V y periodos; restricción de solape; modelo de permisos y alcances; almacenamiento de medios. Solo estructura y enlace al master.

## Out of scope

Cualquier regla de negocio (gate, políticas, periodos, solapes, RBAC real, imágenes). Cambios de UI. Cambiar permisos concedidos. Reescribir tablas de auditoría existentes.

## Dependencies

Ninguna. Es la primera task.

## Domain invariants

- Cero cambio de comportamiento observable en API y UI.
- Los permisos efectivos de `admin`, `trainer`, `reception-management` y `accountant` son idénticos antes y después (golden).
- Todas las acciones y tipos de evento actuales siguen siendo válidos.
- Ningún texto del dominio usa la zona horaria del servidor.

## Files likely affected

`packages/testing/*`, `packages/audit/*`, `packages/permissions/src/index.ts`, `apps/api/src/db.ts`, `apps/api/src/schema.ts`, `apps/api/migrations/` (siguiente número libre), tests de las áreas donde el parser de `date` cambie la forma del dato, `docs/adr/*`.

## Migration

Una migración aditiva: tabla de auditoría compartida; relajación de los CHECK de eventos y notificaciones; función `canary_date`. Test de migración sobre una base con eventos y notificaciones existentes (siguen válidos).

## Feature flags

Ninguno.

## Tests

- Unit del `Clock` y de las utilidades de fecha (fin de mes, 29/02, DST 29/03/2026 y 25/10/2026, paso de año).
- Golden de permisos de los 4 roles; registro: toda clave tiene metadatos; ninguna clave de la lista no delegable es concedida a `trainer`.
- Migración: eventos antiguos válidos; evento nuevo con acción por regex aceptado; regex inválido rechazado; append-only.
- Parser de `date`: lectura de columnas `date` devuelve texto; tests existentes siguen verdes.
- Suite completa sobre base limpia.

## Manual acceptance

Sin UI nueva. Comprobar con `pnpm owner:review` que el piloto arranca y Agenda/Clientes/Tienda se ven igual.

## Risks

- Cambiar el parser de `date` puede romper código que espera `Date` → auditoría previa de usos + tests.
- Relajar CHECK reduce una guarda de BD → compensar con registro en código y test de formato.

## Definition of Done

Suite completa en verde sobre base limpia (cifras en el handoff); golden intacto; sin cambios de comportamiento; migración probada con datos heredados; revisión independiente de SHA exacto; handoff actualizado.

## Handoff requirements

`docs/handoffs/2J-098-0.md`: usos del tipo `date` encontrados y cambiados, clasificación de permisos frente a R-03, lista de acciones/tipos aceptados por el nuevo regex, cifras de validación, estado de CI del SHA exacto.
